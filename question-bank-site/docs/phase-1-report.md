## 2. فحص البيانات — `audit.py`

أُعيدت كتابة السكربت ليتحقق من 20 نوع مشكلة بدلًا من 11. أهم الإضافات:

| فحص جديد | لماذا |
|---|---|
| `ANS_TYPE` / `TF_ANS_TYPE` | `ans` كان يقبل أي شيء؛ الآن `mcq` يجب أن يكون `int` و`tf` يجب أن يكون `bool` |
| `HTML_TAG` / `HTML_DANGEROUS` | يمنع تسلل وسوم HTML إلى القالب |
| `HTML_ENTITY` | يمنع `&nbsp;` وأمثالها من التضاعف عند العرض |
| `CTRL_CHAR` | يمنع محارف التحكم المخفية |
| `BIDI_CHAR` (تحذير) | يكشف محارف إعادة ترتيب النص (انتحال بصري) |
| `EMPTY_SECTION` | قسم فارغ يعطّل الواجهة، فصار خطأً لا تحذيرًا |
| `ID_PREFIX` (تحذير) | يكشف IDs خرجت عن صيغتها الثابتة |
| `MANY_OPTS` / `LONG_STEM` / `LONG_NOTE` (تحذير) | يكشف المدخلات الشاذة |

كما أُضيف:
- **مخرجات إنجليزية/عربية نظيفة** مع ملخص أنواع: `mcq=391 tf=318 note=57 fig=38`
- **رموز خروج**: `0` نظيف، `1` توجد مشاكل — ليوقف CI فعليًا
- **وضع `--strict`**: يحوّل التحذيرات إلى أخطاء

### التحقق أن الفحص يعمل فعلًا

لا قيمة لفحص لم يُجرَّب على بيانات فاسدة. شُغِّل على 19 نسخة فاسدة مصطنعة:


## 3. تأمين عرض المحتوى

**المشكلة:** كل نص من `data.json` (نص السؤال، الخيارات، الشرح، أسماء المقررات والأقسام) كان يُحقن في `innerHTML` بدون أي تهريب. البيانات الحالية نظيفة، لكن أي تعديل مستقبلي كان كافيًا لكسر الصفحة أو تنفيذ كود.

**الحل:** دالة `esc()` واحدة في القالب، وكل مسار عرض يمر عبرها:

```js
const ESC_MAP = { '&':'&amp;', '<':'&lt;', '>':'&gt;', '"':'&quot;', "'":'&#39;' };
function esc(value){
  if (value === null || value === undefined) return '';
  return String(value).replace(/[&<>"']/g, ch => ESC_MAP[ch]);
}
```

**المسارات المؤمّنة:**

| المسار | الحقول |
|---|---|
| `qCard()` — بطاقة السؤال | نص السؤال، الخيارات، الشرح، اسم المقرر والقسم في وضع المراجعة |
| `renderResult()` — شاشة النتيجة | نص السؤال، الإجابات، الشرح، اسم المقرر |
| `renderHome()` — الرئيسية | أسماء المقررات، اسم المقرر في لوحة الاستكمال |
| `renderCourse()` — شاشة المقرر | اسم المقرر، أسماء الأقسام |

**تحسين إضافي:** بطاقة المقرر كانت تستخدم `onclick="openCourse('${c.id}')"` — حقن مباشر في سمة HTML. حُوِّلت إلى `data-course` مع ربط عبر `addEventListener`، فأصبح الـ id يمر عبر `esc()` أيضًا.

**الأثر:** حجم الملف زاد 3.6 KB فقط (520 KB ← 523 KB)، وصفر اختبارات فاشلة.

## 4. الاختبارات الآلية

### البنية

حزمة اختبار بلا إطار عمل: `node tests/run.mjs`. الاعتمادية الخارجية الوحيدة `jsdom` — **أداة اختبار فقط، لا تدخل في بناء الموقع ولا في مسار `python3`**.

| الملف | التغطية |
|---|---|
| `tests/harness.mjs` | محمّل الموقع، `localStorage` مزيف، أدوات تفاعل، مكتبة تأكيدات صغيرة |
| `tests/data.test.mjs` | سلامة البنك + هجمات XSS على كل مسار عرض |
| `tests/quiz.test.mjs` | التدريب، الامتحان، المؤقت، الجلسة، سجل الأخطاء |
| `tests/a11y.test.mjs` | دلالات ARIA واختصارات الكيبورد |

### المبدأ

الاختبارات تحمّل **`index.html` المبني فعلًا** داخل `jsdom` وتستخدمه كما يستخدمه الطالب: نقر على الخيارات، تبديل الوضع، انتهاء الوقت. لا تُختبر نسخة منفصلة من المنطق.

### التحقق أن الاختبارات ليست شكلية

اختبار ينجح دائمًا لا قيمة له. كُسر الموقع عمدًا ثلاث مرات للتأكد أن الحزمة تحمرّ:

| الكسر المتعمّد | النتيجة |
|---|---|
| `esc()` تعيد النص كما هو | ✗ 4 اختبارات فشلت — يكشفه |
| المؤقت لا يسلّم تلقائيًا | ✗ اختبار فشل — يكشفه |
| `esc()` أُزيلت من مسار النتيجة فقط | ✗ اختبار فشل — يكشفه |

> **اكتشاف أثناء العمل:** أول نسخة من اختبار XSS كانت تنجح حتى بعد إزالة التهريب — أي أنها كانت شكلية. السبب أن السؤال المصاب لم يُعرض أصلًا في شاشة النتيجة (الشاشة تعرض الأخطاء فقط). أُضيف تأكيد أن السؤال ظهر فعلًا قبل فحص التهريب، وأُضيف اختبار ثانٍ يستهدف `qCard()` مباشرة. هذا هو نوع الخطأ الذي لا يكشفه إلا كسر الكود عمدًا.

### نظام CI

`.github/workflows/validate.yml` يشغّل الآن 6 خطوات:

1. `audit.py --strict`
2. إعادة بناء `index.html`
3. التحقق أن الملف المبني هو نفسه المرفوع
4. `node --check` على سكربت الموقع
5. حزمة الاختبارات (51 اختبارًا)
6. **وظيفة `mutants`**: تكسر `esc()` والمؤقت عمدًا وتتوقع فشل البناء

الخطوة السادسة هي الضمانة أن الحزمة تبقى ذات قيمة مع الوقت.

## 5. تحسين الوصول

| ما تم | التفصيل |
|---|---|
| **نمط تركيز مرئي** | لم يكن في القالب أي `:focus` إطلاقًا — مستخدم الكيبورد لم يكن يرى موقعه. أُضيف `:focus-visible` بحدود 3px |
| **`aria-live`** | التغذية الراجعة صارت `role="status" aria-live="polite"` — قارئ الشاشة يعلن صحة الإجابة |
| **`radiogroup`** | الخيارات داخل `role="radiogroup"` مرتبطة بنص السؤال عبر `aria-labelledby` |
| **`aria-checked`** | كل خيار `role="radio"` بحالة محدّدة |
| **`aria-label` وصفي** | مثل «أ. الخيار — إجابة صحيحة» بدلًا من نص الخيار وحده |
| **`aria-disabled`** | بعد الإجابة في وضع التدريب |
| **نص لقارئ الشاشة** | «السؤال 3 من 20» و«4 اختيارات. استخدم أرقام 1 إلى 4» |
| **احترام تقليل الحركة** | `prefers-reduced-motion` |

### توسيع اختصارات الكيبورد

كانت تعمل في وضع الامتحان فقط. الآن:

| المفتاح | وضع الامتحان | وضع التدريب |
|---|---|---|
| `1–5` | يجيب السؤال الحالي | يجيب أول سؤال غير مُجاب (أو البطاقة المركّزة) |
| `←` / `→` | تنقّل بين الأسئلة (RTL) | — |
| `Enter` | تسليم في آخر سؤال | إظهار الإجابة |

وأُضيف حاجز: الاختصارات لا تعمل أثناء الكتابة في حقل المؤقت أو أثناء الضغط مع `Ctrl`/`Ctrl`/`Alt`.

## 6. ما لم يُنفَّذ — بند 1.1

> **ملاحظة:** أدوات الاستخراج لا تعمل، وقرار المسار يحتاج قرارك. لم أُلمس `scripts/extract/` كي لا يضيع العمل إن اخترت المسار الآخر.

### الحقائق

| العنصر | الحالة |
|---|---|
| وحدة `layout` | **غير موجودة** في المستودع — يستوردها `build.py` و`make_data.py` |
| `pymupdf` | مستورد في 7 ملفات، غير موثّق في أي `requirements` |
| `fontTools` | يستوردها `pdfbase.py`، غير موثّقة |
| مسار PDF في `make_data.py` | مثبّت: `/home/user/uploads/...` |
| `paths.PDFS` | يشير إلى `pdfs/` غير موجود |
| `make_data.py` مخرج | يكتب إلى `/home/user/site/data.json` — مسار خارج المستودع |

### الخياران

**المسار 1 — إحياء الاستخراج**
استعادة `layout.py`، كتابة `requirements-extract.txt`، إزالة المسارات المطلقة، توثيق أن التشغيل يحتاج ملفات PDF محليًا.
القيمة: إعادة بناء `data.json` من المصدر.
التكلفة: لا أحد غيرك يملك ملفات PDF، فقد يبقى غير قابل للتحقق من طرف ثالث.

**المسار 2 — أرشفة الاستخراج** ← التوصية
نقل إلى `scripts/archive/extract/`، توثيقه كأداة تاريخية، إعلان `src/data.json` مصدر الحقيقة الوحيد.
القيمة: المرحلة التالية (سجل المحاولات، المراجعة الذكية) تبدأ فورًا بلا دين تقني.

## 8. الخطوة التالية المقترحة

بعد حسم بند 1.1، المرحلة الثانية تبدأ بـ **سجل المحاولات** قبل المراجعة الذكية ولوحة التحليلات، لأن كليهما يحتاج بيانات محاولات تاريخية.
